# Flock Energy Take-Home: REFIT Data Cleaning and Washing-Machine Disaggregation

A reproducible pipeline on the University of Strathclyde **REFIT** electrical-load dataset. It has four parts:

1. **Phase 1:** inspect and clean **raw** House 1 data into a 1-minute series.
2. **Phase 2:** explore washing-machine use in **six homes** from the official cleaned data.
3. **Phase 3:** build and evaluate a **LightGBM disaggregation model** that estimates washing-machine power from
   whole-house power, against simple baselines.
4. **Phase 4:** turn the results into a **utility-facing recommendation**.

Each phase is a script plus a notebook that imports it, so both produce identical outputs. Every reported number
is written to `outputs/tables/` by code.

## Headline results

- **Cleaning (Phase 1).** The raw `Unix` column is the UK local clock, not UTC. After conversion, the 1-minute
  resampling conserves the energy of the observed signal: cleaned and raw energy agree within 0.31% in three test
  windows and within 0.09% per channel over the full record.
- **EDA (Phase 2).**
  - 2,678 likely wash cycles were found.
  - A typical cycle uses 0.29–0.79 kWh and lasts 45–98 min (house medians), with a ~2 kW heating block.
  - Homes wash 3.5–10.9 times a week, and washing is 2.7–6.8% of household electricity.
  - Timing is household-specific.
- **Model (Phase 3), pooled test period.** RMSE is 128 W, against 220 W for always-off and 217 W for the
  hour-of-day profile. Minute F1 is 0.56. Cycle detection, scored one-to-one at IoU ≥ 0.5:

  | Setting | Recall | Precision | F1 |
  |---|---|---|---|
  | Unseen time | 77.6% | 40.6% | 0.53 |
  | Unseen homes | 68.9% | 28.1% | 0.40 |

- **Recommendation (Phase 4).** Encourage customers to move washes out of the evening peak; this is peak
  reduction, not energy saving. The washing machine adds about 21 W per home to the 16:00–19:00 window, so the
  idea works best as targeted messaging or as part of a wider flexible-load offer. Prove it with a randomised
  trial measured on meter data. The model is a screening tool, not a measurement tool.

## Setup

1. Install Python 3.10 or later (tested with 3.13.5), then the packages:
   ```bash
   pip install -r requirements.txt
   ```
2. Download the two REFIT archives and extract them into `Data/`:
   - raw: https://pureportal.strath.ac.uk/files/62090177/REFIT_RAW_081116.7z
   - cleaned: https://pureportal.strath.ac.uk/files/62090184/CLEAN_REFIT_081116.7z

   For example, `7z x REFIT_RAW_081116.7z -oData/REFIT_RAW_081116`. The files must end up at
   `Data/REFIT_RAW_081116/RAW_House1_Part1.csv` and `Data/CLEAN_REFIT_081116/CLEAN_House2.csv`. The archives total
   about 14 GB once extracted.

## Run

```bash
./run_all.sh               # all four phases, about 3 minutes in total
./run_all.sh --notebooks   # also re-executes the four notebooks
```

Or run each phase on its own, in this order (Phase 4 reads Phase 3's test predictions):

```bash
python3 phase1/run_cleaning.py      # House 1 cleaning; writes only if all 37 assertions pass
python3 phase2/wm_eda.py            # EDA
python3 phase3/wm_nilm.py           # model training and evaluation (about 2 min)
```

All scripts locate the repository root themselves, so they run from any folder. Running `run_all.sh` on a fresh
copy reproduced all 55 tables exactly and all 23 figures.

## Assumptions

Each assumption is recorded where it arises, as `> **Assumption:**` notes in the notebooks and phase docs. The
main ones:

- **Phase 1 timestamps.** The raw `Time` column is the UK wall clock. Evidence: clock-change signatures, agreement
  between Part 1 and Part 2, and agreement with the official file for Part 1.
- **Phases 2–4 timestamps.** The official cleaned `Unix` column is treated as UTC, and hours are converted to UK
  local time. See the open issue under Known issues.
- **Ground truth.** The 1-minute mean of the washing-machine sub-meter is treated as true washing-machine power.
- **Washing-machine channels.** Taken from the REFIT readme. House 5's channel is treated as a probable
  washer-dryer: it is kept for the EDA and excluded from modelling.
- **Peak window.** "Peak" means weekdays 16:00–19:00 on the UK local clock. This is a study choice, not an official
  definition.

## Preprocessing decisions

- **Phase 1:**
  - Convert to UTC.
  - Readings above 4 kW (appliances) or 25 kW (aggregate), and negative readings, are set to missing.
  - Duplicate seconds keep the last non-missing reading per channel.
  - Short gaps are bridged by holding each reading for at most 60 or 120 s.
  - Outages are flagged and left missing.
  - 1-minute values are exact time-weighted means, kept only with at least 30 s of coverage.
- **Phases 2–3:**
  - Sort the readings and drop duplicate timestamps.
  - Mask frozen values (held for more than 60 min).
  - Take 1-minute means, with no gap filling.
  - Phase 3 also drops unreliable days (60 or more frozen aggregate minutes) and inconsistent minutes (washing
    machine more than 100 W above the aggregate).
- **Cycle rule:** active above 20 W; pauses of up to 15 min joined; a cycle lasts 10–300 min, uses at least
  0.05 kWh and peaks above 200 W.

## Validation design

- **Phase 1.** The pipeline runs 37 assertions before writing anything:
  - timestamp order and clock changes;
  - the handoff and duplicate merging;
  - physical limits and minute coverage;
  - that outages stay missing;
  - exact energy conservation.

  Energy is also checked against exact raw integrals over identical half-open windows.
- **Phase 3, split.** Each house's data is split in time order, 60/20/20, with 1-day buffers, so no ±60-minute
  feature window spans two splits.
- **Phase 3, use of each split.** The threshold τ and early stopping use validation data only. The test data are
  scored once.
- **Phase 3, unseen homes.** Leave-one-house-out tests homes the model has never seen. Each fold chooses its own τ
  without the held-out house, and a check confirms this.
- **Phase 3, metrics.** Results are reported at minute, energy and cycle level against two baselines. Cycles are
  matched one-to-one at IoU ≥ 0.5, fixed before evaluation; "any overlap" is reported only as a sensitivity check.

## Trade-offs

- **LightGBM over a neural network.** It is fast (seconds per fit), handles missing values and is easy to explain.
  It is not state of the art; a Seq2Point CNN might detect cycles better.
- **A centred ±60-minute window.** This gives better accuracy, but an estimate exists only 60 min after the fact. A
  causal variant (past 60 min only) is reported and is weaker.
- **Chronological split.** This is realistic and avoids leakage, but the test periods are in 2015, so seasonal
  change is mixed in with model error.
- **Conservative missing-data rules.** Gaps are not filled beyond 60–120 s, so analyses use less data but nothing
  is invented.
- **Scope.** A manageable six homes for the EDA and five for modelling, rather than all twenty.

## Known issues and open questions

1. **The official REFIT cleaned files appear to use UK local time, not UTC, in Part 2's summer-time periods.** All
   seven files checked show an empty 01:00 UTC hour on 29 Mar 2015, and six show a doubled hour on 26 Oct 2014
   ([phase1/RESULTS.md §2](phase1/RESULTS.md)). Phases 2–4 treat the official timestamps as UTC, so hour-of-day
   results, such as Phase 4's peak window, may be shifted by one hour in those periods. This has **not been
   corrected**. A fix would re-derive the clock offset per house and period from the raw files before Phases 2–4.
2. **Phase 1 logger clocks.** The two House 1 logger clocks drift apart by up to 7 min in summer 2014, and there
   is no reference clock. Two UTC hours on 26 Oct 2014 are removed because the repeated hour cannot be split.

## Possible improvements

- **Fix the timestamp issue first.** Correct the official-file clock periods (Known issues 1), then rerun the
  hour-of-day analyses.
- **Try a sequence model.** A Seq2Point or sequence-to-sequence CNN could be compared against LightGBM on the same
  split.
- **Use more households.** Sixteen REFIT homes have a dedicated washing-machine channel.
- **Add features.** Explicit step-change and heater-shape features might reduce confusion with kettles,
  dishwashers and dryers.
- **Deployment-style tests.** Test on 15- and 30-minute data with a model retrained at that resolution; Phase 4
  only illustrates the information loss.
- **Calibrate per home.** A short local calibration period for each new home could address the leave-one-house-out
  drop.
